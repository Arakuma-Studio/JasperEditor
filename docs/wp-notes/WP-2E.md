## Integration notes (for WP-2A / WP-2F / WP-3I)

- **WP-2F must**: honor `takeOver: true` on `POST …/lease` (revoke the holder, answer the old lease id with 404 `LEASE_NOT_FOUND` or 409 `LEASE_HELD` afterwards); treat a re-acquire with the **same** `sessionId` as a renewal; answer `DELETE …/lease/:id` for keepalive requests; return **every** derivative kind in `GET /api/media/:key` and `media.updated` (`z.record(DerivativeKindSchema, …)` is exhaustive in zod 4 — a partial map fails client parsing); ideally set `EngineJob.assetId = mediaKey` for derivative jobs (the runtime sync maps jobs to media by `assetId`, falling back to the fingerprint suffix of `dedupeKey`); include `planId` + `documentRevision` in plans; put `{blockers}` in the `PATH_NOT_ELIGIBLE` error detail.
- **WP-2A**: Ctrl+S (`app.save`) → `persistenceFor(ctx.session)?.flush()`; header dirty dot/"Saving…" → `usePersistenceStatus`; header jobs badge → `useJobsSummary()` from `panels/jobs`; Export tab → `exportMode.open(seqId)` / `useExportMode()` (render `<ExportMode/>` in the mode area and drop the overlay in ProjectLifecycle if preferred); route `ctx.ui.toast` to your toast host or mount `<NoticeHost/>`; `edit.clear` (Delete) should run `project.deleteItems` when the Project panel is focused (the panel also handles Delete/Enter/arrows locally); register `panel.open.jobs` so Export can focus the Jobs panel.
- **WP-2B / WP-2C**: on drop call `getImportService()?.readDataTransfer(dt)` then `importFiles({files}, {kind:'timeline', …})` or `placeItems(payload, target)` and `preventDefault()` so ProjectLifecycle's fallback does not import a second time. Register `source.open` (args `{itemId}`) for Project double-click.

## Deviations and TODOs

- `EngineProjectStore.restoreVersion` throws `NOT_IMPLEMENTED`: M1 has no route to read a version's content (`GET /api/projects/:pid/versions/:vid` needed). Version *creation* (every 5 min / before migrations, PER-020) is engine-side.
- Export settings are remembered per sequence in `localStorage`, not in the document (S05:EX-014 says document metadata, non-undoable; there is no non-undoable document channel in M1).
- Desktop OS-file drops upload the bytes (Electron ≥ 32 removed `File.path` and the preload bridge has no `getPathForFile`); File ▸ Import on desktop registers paths in place.
- Export preview shows the poster of the clip at the range start instead of a Player frame (the Program player is WP-2C's; no shared handle yet).
- Destinations other than Media File, presets other than "Match Sequence – H.264", captions/effects sections and Add-to-Queue in Export mode are not in the M1 subset (Quick Export / `export.queue` cover queuing).
- Color Matte is hidden while `synthetic.create` returns `E_NOT_IMPLEMENTED` (M2).
- Take over depends on WP-2F implementing `takeOver`; otherwise the user sees "The other session still holds the project" with the lease expiry time.

## Review (WP-2E reviewer, 2026-09-30)

- Re-ran `pnpm install && pnpm lint && pnpm typecheck && pnpm test && pnpm build` in this worktree: all green.
- Real-engine check: a scratch worktree of this branch merged with `wp/wp-2f` (merges cleanly), engine serving the built SPA. Worked end to end: Home → New Project → editor; dropping clip-a.mp4, tone.wav and still.png uploaded and committed one transaction (engine revision 1, 3 assets with `engine-store` locators); posters in Icon view; reload reopened the project editable with its items (the lease was released on unload); a server-side save produced the 409 banner and Reload showed the server document; Export mode planned "Auto → Native (ffmpeg)", Export ran the job, and the "Export finished" toast's Download returned the MP4; a second tab opened read-only.
- As expected, wp/wp-2f does not implement `takeOver` yet. "Take over editing" then shows "The other session still holds the project" and the lease expiry time.
- Fix: `EngineProjectStore` attached a `pagehide` listener in its constructor and never removed it. That leaked one listener and one store per Home mount and per project open. The listener is now attached only while the store holds leases.
- Known gap: the keepalive lease release (`pagehide`) sends cookies but no `Authorization: Bearer` header. With the token-only auth mode (no cookie), the lease is not released and simply expires after its TTL.
- For WP-2F/integration: the engine's static SPA handler only serves asset files that existed at startup, so rebuilding `apps/web/dist` while the engine runs gives 404s for the new hashed bundle.
- Without WP-2A there is no global keyboard dispatcher, so Ctrl+M / Ctrl+I do nothing in the placeholder shell. They start working once WP-2A binds `keymap-defaults.ts`.
