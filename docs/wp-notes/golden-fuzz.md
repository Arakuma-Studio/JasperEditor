# golden-fuzz: golden frames, fuzzing, oracles, scale benchmark, CI

Evidence that features stay correct (docs/gaps.md "golden-fuzz"): golden frames and fingerprints pin rendered
output, parser, loader and HTTP fuzz targets exercise malformed inputs, ffmpeg serves as an
oracle with a require-switch, a scale benchmark keeps everyday operations fast on a 5,000-clip project, and a
GitHub Actions workflow runs the gate. The user guide is [docs/testing.md](../testing.md); this note records
design, decisions, verified behaviour and limits.

## Design

**`@jasper/testkit`** (`packages/testkit`, a devDependency only; a row in ARCHITECTURE §3.1 and `LAYERS`):

| Module | Contents |
|---|---|
| `golden.ts` | `diffImages` (max, mean, p99, PSNR, differing), `Tolerance` (`EXACT`, `RENDER`, `GL`, `BROWSER`), `expectGolden` / `checkGolden` (bless with `JASPER_BLESS=1`, 50 KB cap, actual / expected / ×8 diff to `test-results/golden-failures/`, `.attribution` sidecar + `ATTRIBUTION.md` row on bless), `expectFingerprints` (4×4 mean RGB, ±levels, NaN-aware), `expectPins` |
| `png.ts`, `image.ts` | PNG codec on node:zlib (all colour types and depths, Adam7, CRC, bounded inflate; `PngError`); RGBA8 helpers, `meanGrid`, `fnv1a`. `image.ts` is DOM- and Node-free, so GL test entries bundle it |
| `fuzz.ts` | `Rng` (xorshift128 seeded by splitmix32), byte / text / JSON-structure mutators, `bytesTarget` / `textTarget` / `jsonTarget`, `describeFuzz`, `runFuzzTarget(Sync)`, `assertFuzzSync`; failing inputs saved to `test-results/fuzz-failures/`; `FUZZ=1`, `FUZZ_SEED` |
| `oracle.ts` | ffmpeg / ffprobe discovery (`JASPER_FFMPEG` / `JASPER_FFPROBE`, PATH, known dirs), `JASPER_REQUIRE_ORACLES=1`, `requireTool` / `oraclesAvailable` / `skipOracle`, EBU R128 (`measureLoudness`, `parseEbur128`), PSNR / SSIM (`compareVideos`), packet / frame tables (`probePackets`, `probeFrames`, `compareTables`), `decodeFrames`, `ffmpeg` |
| `browser.ts` | Chrome discovery, SwiftShader flags, esbuild bundling (the compositions GL suites open pages through `packages/compositions/test/gl-browser.ts`) |

**GL tests.** Fingerprints compare rendered output in the per-family catalogue runs:
`fx-fingerprints.json` covers GPU effects at defaults and with perturbed parameters, and
`transition-fingerprints.json` covers GPU transitions at p = 0.25 / 0.5 / 0.75 over two cards.

**Golden scenes.** `packages/compositions/test/golden/scenes.ts` (56 procedural 256×144 scenes, rendered by Remotion
in `golden-scenes.e2e.test.ts`) and `apps/engine/test/golden-parity.e2e.test.ts` (5 compositor scenes rendered by
the native path and by Remotion). Pictures are generated by the test (`goldenCard`, `goldenTile`), the movie by
ffmpeg (`testsrc2`), text uses the repository's Inter (every font resolves to it, so glyphs match on every machine).
**Decision:** the scene suites are gated by `REMOTION_E2E=1` like every Remotion render suite (bundling ≈ 15–40 s);
the GL fingerprints and motion-blur goldens run by default where a Chrome exists (CI included).

**Motion-blur pins.** The 36 checksum pins of `fx-motion-blur/baseline.json` became golden PNGs. They were blessed
from the same output, and every PNG's pixel checksum equals the former pin (checked once, 36/36, before the JSON was
removed), so the "identical to the pre-wave-5 output" claim carries over. Tolerance PSNR ≥ 45 / max ≤ 16 / p99 ≤ 2
(the old exact checksum would also break on a Chrome/SwiftShader update; a real change moves far more). The three
perspective-warp PNGs exceed the 50 KB cap (56–109 KB) and pass a 128 KB cap explicitly.

**Fuzz targets.** One-line registration per target (docs/testing.md §4). They cover:

- `@jasper/project`: 34 targets, in `test/fuzz-parsers.test.ts`.
- `@jasper/interchange`: every format end to end into a project. The per-format corruption tests now run on the
  harness (`expectOnlyInterchangeErrors` = `assertFuzzSync`, with the old 64-point truncation grid kept).
- `@jasper/expressions`.
- `@jasper/engine`: archives, PSD, Lottie, ffprobe JSON, bundle metadata, names, runtime file and events.
  `test/fuzz-http.test.ts` covers every HTTP route (123 method/path pairs, taken from the server's own route table).
- `@jasper/testkit`: its PNG decoder.

**Scale benchmark.** `packages/project/bench/scale-project.ts` builds 200 sequences / 5,000 clips / 1,600 effects /
5,000 keyframes through the command system; `packages/session/bench/scale.ts` times load, migrate (v1 → current),
invariants, small and 300-clip edits through `EditorSession`, undo, redo, render snapshots, scene resolution and the
autosave serialisation, against budgets scaled by a measured load factor (`PERF=1` exact,
`JASPER_PERF_NO_BUDGET=1` report only). It runs in `pnpm perf` and writes `scale.results.json`, before and after
included.

**CI.** `.github/workflows/ci.yml`: lint, typecheck, `pnpm test --maxWorkers=2`, build on push and PR, ffmpeg from
apt, `JASPER_REQUIRE_ORACLES=1`, SwiftShader in the runner's Chrome, no LGPL FFmpeg, no opt-in suites, failure
artefacts uploaded. `actionlint` 1.7.12 passes. Timing budgets stay load-tolerant (no `PERF=1`), consistent with the
`previews` workstream's budget policy.

**Fidelity.** No capture harness against Adobe software (scope change, BRIEF §3b); `docs/fidelity/README.md` states
the research-based approach and what our own oracles measure.

## Bugs found and fixed

| Found by | Bug | Fix | Regression test |
|---|---|---|---|
| scale generator | the per-track clip index and the sequence duration were memoized on the Immer draft's identity, so later commands of one transaction missed clips added by earlier ones (`transition.add` at a new clip's edge failed "not an edit point") | never memoize drafts (`derive/index.ts`) | `derive-draft.test.ts` |
| fuzz: engine | a zip entry offset or size past the end of the file reached `fh.read` with an out-of-range length and **aborted the engine process** in a native assertion; corrupt deflate data and NUL bytes in names threw untyped errors | bounds-checked `readAt`, zip64 extra-field checks, `ZipError` for inflate failures and NUL names (`mg-bundles/zip.ts`) | `fuzz-regressions.test.ts` |
| fuzz: engine | ffprobe JSON with an unexpected type (a number for `r_frame_rate`, an object for `tags`…) crashed the mapping with a TypeError; absurd durations and bit depths produced probes that fail the media schema | `sanitizeProbeJson` coerces the shapes and ranges before `mapProbe` (`media/probe.ts`) | `fuzz-regressions.test.ts` |
| fuzz: project | SVG import recursed forever (stack overflow) on a group transform inside a degenerate (skewed) matrix | the group's transform is composed into the baked matrix (`vector/svg-import.ts`) | `fuzz-regressions.test.ts` |
| fuzz: project | glTF / GLB / OBJ: invalid UTF-8 threw `RangeError`, a broken GLB JSON chunk `SyntaxError`, structurally wrong JSON `TypeError` | U+FFFD for bad code points, `ModelParseError` everywhere (`three-d/gltf.ts`) | `fuzz-regressions.test.ts` |
| fuzz: project | a reference named like an `Object.prototype` member (`mediaId: "__proto__"`) crashed the invariant check | loaded documents' id tables are null-prototype records (`nullPrototypeRecords`) | `fuzz-regressions.test.ts` |
| fuzz: project | load left invariant violations that make every later edit fail: record keys ≠ ids, malformed and duplicate ids, link/group keys, tracks of the wrong kind in a list, impossible frame sizes / rates / drop-frame, text with a missing font, out-of-range opacity and shape values, clips past their media, a derived medium whose source is gone, transitions no longer fitting their clips | `repairIds` (structured INV-001 issues), `repairStructure`, `repairShapeValues`, `repairMediaBounds`, `repairTransitionsFinal` in `invariants.ts` | `fuzz-regressions.test.ts`, the load fuzz target (asserts zero issues after load) |
| fuzz: project | `parseSvgPath` and `loadProject` / `migrate` threw plain `Error` | `SvgPathError`, `ProjectLoadError` (both extend `Error`, existing callers unchanged) | fuzz targets |
| fuzz kit self-test | (in the new code) optional-call short-circuit skipped running a target | fixed before use | `packages/testkit/test/fuzz.test.ts` |

## Performance (scale benchmark)

These numbers were measured with `pnpm exec tsx packages/session/bench/scale.ts` on 12 cores at load average ≈ 10
(Node 20.20). "Before" is cc1c2f88 (the proxy-free scans were already in); "after" is this branch. Medians:

| Operation | Before | After | Budget (reference ms, × load) |
|---|---|---|---|
| load (parse + migrate + zod + invariants) | 885 ms | 774 ms | 2,500 |
| migrate v1 → current | 159 ms | 159 ms | 1,500 |
| invariants (whole document) | 438 ms | 25 ms | 600 |
| small edit (one Opacity value) | **511 ms (over budget)** | 76 ms | 250 |
| large edit (300 clips, one transaction) | 2,112 ms | 355 ms | 2,000 |
| undo / redo | 0.2 / 0.2 ms | 0.2 / 0.1 ms | 50 |
| render snapshot (one / all 200 sequences) | 0.7 / 130 ms | 0.8 / 147 ms | 40 / 3,000 |
| autosave serialisation | 70 ms | 66 ms | 1,200 |

The 5,000-clip project was originally built in 137 s and now builds in 46 s.

Hot spots fixed:

- **Transactions read the whole document through the Immer draft.** Clip and effect lookup, shape centring,
  orphan collection and `idExists` did this. A `peek` helper now reads own properties without creating drafts,
  and per-record results are memoized for untouched (non-draft) records.
- **Shape centring scanned every shape for every command.** A command that names its clips now only checks those
  clips. Keyframe ids, `$selection` and commands that name no clip still check every shape.
- **Every transaction re-checked every sequence's invariants.** A frozen (immutable) sequence that a transaction
  left untouched now replays its memoized findings: ids into the duplicate check, references, issues. The memo is
  skipped in these cases:
  - sequences with nests or multicam references;
  - order-dependent caption-transcript counting;
  - duplicate ids (those fall back to the uncached walk).
- **Expression issues were recomputed for every sequence.** They are now memoized per frozen sequence, and a
  sequence without expressions skips `allowedTargets`.

`invariants-memo.test.ts` checks that duplicate clip IDs and missing media are reported after earlier
validation of shared sequences, through the public `checkInvariants` entry point.

## Verified behaviour

- `packages/testkit`: metrics, PNG codec, blessing and size cap, fingerprints, pins, fuzz verdicts and artifacts,
  tool discovery, ebur128 parsing, live ffmpeg loudness (a −20 dBFS 1 kHz sine measures −20.0 LUFS ±0.1),
  PSNR/SSIM, packet / frame tables.
- Golden scenes retain committed frame references, with independent computed references where available.
  Native/Remotion parity also compares each scene with its committed reference. These pixel comparisons detect
  missing or incorrect renders without an additional scene-count or pairwise-distinctness requirement.
- Native vs Remotion parity, from `test-results/golden/parity.txt`:

  | Scene | PSNR | max | p99 |
  |---|---|---|---|
  | transform + opacity | 56.1 dB | 11 | 2 |
  | crop | 51.9 dB | 23 | 0 |
  | screen | 60.1 dB | 2 | 1 |
  | linear burn | 65.5 dB | 7 | 1 |
  | colour run | 91.4 dB | 1 | 0 |

  The test requires PSNR ≥ 45 dB, max ≤ 32 and p99 ≤ 3.
- GL fingerprints were blessed and re-run stable. The motion-blur goldens equal the old checksums.
- Historical validation before test cleanup: long fuzz runs found nothing further:
  - `FUZZ=1` on seeds 7, 99, 1234 and 31337 for the project parsers;
  - default runs for the interchange, engine, HTTP and MCP targets.

## Limits

- **Blend modes in the golden scenes.** The Remotion path cannot stack two tracks with GPU-composited blend modes
  (HTML-in-Canvas scopes do not nest: CANVAS_NESTED, documented in docs/gaps.md and the color-mgmt note). So each
  GL mode has its own scene, and the CSS modes are stacked. The native path stacks every mode; it is covered by
  `blend-export.test.ts`.
- **Golden scenes and parity are opt-in** (`REMOTION_E2E=1`), as all Remotion render suites are. CI runs the GL
  fingerprints, the motion-blur goldens and every fuzz target, but not the Remotion stills.
- **Goldens were blessed on this machine's Chrome / SwiftShader / ffmpeg.** The tolerances are chosen to absorb
  version differences. A first CI run on another Chrome could still need a re-bless, after review.
- **Effects that are identities on a still keep identical fingerprints.** These are time effects that need
  samples, and mattes that need other layers. Their family GL tests cover them.
- **The HTTP fuzz sends junk, not valid requests.** It covers argument validation and error typing. It does not
  start real long jobs, because exports and installs refuse the junk.
- **No Adobe comparison** (BRIEF §3b).
