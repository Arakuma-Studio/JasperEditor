# Engine core code-quality audit

Scope: `apps/engine/src` entry points, routes, agent relay and approval handling, authentication, projects and recovery, jobs, events, uploads, and cache. Related API/project definitions, engine tests, `AGENTS.md`, `CLAUDE.md`, architecture sections 4/9/11, project-file documentation, and WP-2F/WP-2H notes establish the contracts used below. Research used the installed source and shared package schemas; no external code or assets were introduced.

## Critical assessment and implemented recommendations

| Finding | Assessment and resulting change |
| --- | --- |
| Agent envelopes were `Record<string, unknown>` with double assertions in the filesystem adapter. | The engine already has `@jasper/api`'s `EnvelopeJson`: a known envelope around an intentionally opaque document that can belong to an older/newer schema. The project store, agent store, capture request, and headless transaction path now share it. Removing document opacity would incorrectly claim that disk data has passed migration/validation. |
| Recovery metadata and lease summaries duplicated shared contracts. | Recovery metadata derives from API `RecoveryInfo`; journal writes use `RecoveryPutRequest`; agent lease summaries use `Pick<Lease, ...>`. Journal metadata is validated by the existing API schema before listing. |
| Project loading reported corrupt files as missing and directory read errors as an empty project list. | The store distinguishes absence from read failures and parses the envelope with `EnvelopeSchema`. Invalid JSON/envelopes receive an actionable 422 error and retain their original bytes. Revision lookup only converts `PROJECT_NOT_FOUND` into null. Version-directory and stat errors also propagate unless the path disappeared. Project enumeration continues to omit malformed entries without deleting them; directly opening their known ID reports the precise error. |
| Recovery listing deleted entire session directories if metadata or snapshots were unreadable. | An interrupted write may leave a valid unsaved snapshot without its metadata. Listing now refuses with a preserved-data error identifying the project/session, rather than deleting anything it cannot validate. Only a validated snapshot equal to the saved project is removed automatically. The snapshot limit measures UTF-8 bytes. |
| Job failure handling asserted that every rejection had error properties. | A runner rejecting with null/undefined, numeric fields, or a null-prototype object could throw inside its catch, leaving the job running and slots occupied. The boundary narrows optional fields and always produces a string code/message; valid tool error codes, retry policy, and stderr are preserved. |
| Background upload cleanup had unhandled rejections and allowed duplicate interval registration. | Sweep failures report through the service's error callback; start is idempotent and stop clears its handle. Core-service logging is wired by the engine-media audit. Missing upload bytes now require a new upload rather than masquerading as offset zero. Non-absence I/O errors and rollback failures propagate. |
| Audio, speech, camera-tracking, scene-detection, roto, and layer-bake routes repeated completion/error handling. | `jobs/reply.ts` shares their identical 202-or-wait behavior using `EngineJob`, `JobQueue`, and `FastifyReply`. Distinct bundle failure status mapping and preview response behavior remain local because they are different contracts. |
| Cookie, signed-URL, and approval checks repeated constant-time byte comparison. | `auth/secrets.ts` shares the existing length check plus `timingSafeEqual`; no authorization policy, key scope, or comparison behavior changes. |
| Event buffering erased a known type and cast it back later. | The stream's write function and replay buffer retain `EventEnvelope` throughout. Internal still-job polling uses `EngineJob` and its actual state union instead of an invented reply shape and `as never`. |
| Comments restated route declarations or preserved workstream history. | Removed redundant route inventories, ownership headers, and obvious section labels. Kept security, protocol, recovery, cache-protection, and plugin-order constraints; registration-order comments now explain their dependencies directly. |

## Boundaries deliberately retained

- `unknown` remains appropriate at HTTP/JSON, WebSocket, heterogeneous job-input/result, schema, plugin-service, and caught-error boundaries. Treating such values as trusted project objects would weaken validation. There is no explicit `any` introduced by this change.
- Auth parsing catches malformed cookies/origins; relay and event fan-out contain socket/subscriber failures; job catches translate worker failures; recovery loading handles interrupted files. These have specific failure-containment roles and must remain.
- Filesystem recovery conventions are being tightened in the engine-media audit's shared `tools/fs.ts`: absence/JSON parse failure are distinct from permission, full-disk, and I/O failures. Cache scanners retain their conservative handling of vanished files, busy holders, failed moves, and rollback. A broad removal of those handlers would make cleanup less safe.
- Older project schema loading, schema backups, lease takeover, expired-lease headless execution, interrupted-job recovery, and multi-platform startup paths remain supported behavior. No shipped migration or format version was changed.
- Engine-export's TypeScript AST audit found zero strongly connected components in static relative runtime imports across 253 engine source files, excluding type-only imports. This establishes no local runtime import cycle under that analysis; dynamic imports and external packages were outside that scan.
- A corrupt journal now blocks listing until it is repaired or explicitly discarded, while reading a known valid session remains independent of other journals. This is intentional conservative behavior: the API cannot safely invent history metadata, and the response identifies the preserved session. No automatic repair or claim of recovered edits is made.

## Verification

Regression/property coverage exercises malformed project envelopes, incomplete recovery metadata with preserved snapshot bytes, filesystem read failures, non-Error runner rejections releasing CPU slots, missing upload data, and background sweep failures/idempotent lifecycle. Existing agent, jobs, events, upload, recovery/version, audio, and speech suites cover unchanged contracts. Property tests use `fast-check` with 20 generated invalid values per persistence property.

The targeted Biome checks and `git diff --check` pass. Focused Vitest execution uses `--maxWorkers=1`; results are recorded in the integration report. An engine typecheck was started but deliberately stopped at the integrator's request because simultaneous checks were saturating the shared host; final typechecking is serialized by the integrator. This note does not claim an unfinished check passed.
