# wp fonts — the user font library (install a font once, use it in every project)

Branch `feat/pp-font-library`. The user's Premiere projects use fonts JasperEditor does not ship (`Pixel12x10` in
≈ 9 400 text layers, `CircularStd-Medium`, `MinionPro-Regular`, `Earthbound-CondensedBold` — Premiere stores
PostScript names). Before this work, text resolved only against the ten bundled @fontsource families and otherwise
fell back to Source Sans 3 (`FONT_FALLBACK`); `FontSourceSchema.asset` existed but nothing rendered it.

## What was built

| Area | Where | Notes |
|---|---|---|
| Reader | `apps/engine/src/fonts/sfnt.ts` | TrueType/OpenType (`0x00010000`, `true`, `OTTO`), TTC (`ttcf` v1/v2; every face rebuilt as a standalone sfnt — tables copied, 4-byte aligned, checksums kept), WOFF 1.0 (per-table zlib, `inflateSync` with `maxOutputLength` = declared length), WOFF 2.0 (one brotli stream, `brotliDecompressSync` with `maxOutputLength` = sum of the directory's lengths; `name`/`OS/2`/`head`/`fvar`/`cmap` are never transformed, so they are read from the stream directly; glyf/loca/hmtx transforms are not decoded). Type 1 and WOFF/WOFF2 collections are refused (`FONT_UNSUPPORTED`). Requires `head` (magic `0x5F0F3CF5`, unitsPerEm 16…16384), `name`, `cmap` and outlines (`glyf`+`loca`, `CFF `/`CFF2`, or colour/bitmap tables). Names: ID 16/17 (typographic family/subfamily) preferred over 1/2; ID 4 full name; ID 6 PostScript name (printable ASCII minus `[](){}<>/%`, ≤ 63); the legacy family (ID 1) is kept when it differs. Record preference: Windows en-US, Windows, Unicode, Mac Roman (decoded with the Mac OS Roman table). Weight = OS/2 `usWeightClass` (1…9 scale × 100), else 700/400 from `head.macStyle`; italic = `fsSelection` bit 0 (ITALIC) or bit 9 (OBLIQUE), else `macStyle` bit 1. Variable fonts: `fvar` axes (Fixed 16.16). |
| Bounds | same | File ≤ 64 MiB, decompressed tables ≤ 128 MiB, ≤ 256 tables, ≤ 64 faces per collection, ≤ 128 characters per name, ≤ 64 axes. Every offset/count is checked against the buffer; any other exception is converted to `FONT_INVALID`, so the reader throws only `FontParseError`. |
| Store | `apps/engine/src/fonts/library.ts` (`<appdir>/fonts/library.json`, `<appdir>/fonts/files/<id>.<ext>`, `appdirPaths().fontsDir`) | Same pattern as the effect preset library (`effect-presets/library.ts`): serialized mutations, `revision` per change, `fonts.changed {revision}` event; writes through `atomicWriteFile`/`atomicWriteJson` (temp, fsync, rename, directory fsync). Face id = `f` + 24 hex digits of the file's SHA-256 (content-addressed, immutable URLs). Install writes the face files before the index; removal deletes the file before the index entry (a crash never resurrects a removed font). Same bytes again = "existing"; a different file whose face has an installed PostScript name is refused (`FONT_EXISTS`, 409); caps 1 000 faces / 2 GiB (`FONT_LIBRARY_FULL`). |
| Repair on open | same | Unreadable index → kept as `library.json.corrupt-<time>`, rebuilt from the files; entries that fail `LibraryFontSchema` kept in `invalid` (written back); entries whose file is missing dropped; a file whose size changed is re-read and dropped when it no longer reads as that face; stray `<id>.<ext>` files (an install interrupted before the index write) re-parsed and adopted when the hash matches the name; temp files removed. Every repair is a line in `repairs` (shown in Preferences ▸ Fonts and `list_fonts`). An index with `version` > 1 (a newer build) is listed but never rewritten (`readOnly`; install/remove → `FONT_LIBRARY_READ_ONLY`). |
| Catalog | `apps/engine/src/fonts/catalog.ts` | `GET /api/fonts` = bundled families, then library families (`source: 'custom'`, files with `postscriptName`, `fullName`, `legacyFamily`, `fontId`; variable faces listed under 100…900 within their `wght` range, one URL). Files served at `/fonts/library/<id>.<ext>` (validated name, immutable cache). `capabilities.fonts.customUpload` = true. |
| Resolution | `resolveCatalogFont` in `packages/api/src/fonts.ts`, used by the engine (`FontCatalogService.resolve`: planner, export service, layer bake, stills) **and** the web Player (`render-doc.ts`), so preview and exports pick the same file | 1. family equal (case-insensitive) — bundled first, so they win a clash; 2. family equal ignoring case, spaces, `-`, `_`; 3. a face whose PostScript, full or legacy family name matches loosely → that face whatever the requested weight. In a family: `latin` subset (or no subset), italic faces for italic text when present, nearest weight. The browser registers the face under the document's family name at the requested weight (`packages/compositions/src/fonts.ts`), so a PostScript-name match draws the face without synthetic bold. Unmatched → Source Sans 3 and `FONT_FALLBACK`, whose message now names the missing families. The remote platform fonts of the social-comment templates (`source: 'remote'`, [social-comments](social-comments.md)) are skipped: they are template faces, never text fonts (also left out of the font menus, Preferences ▸ Fonts and MCP `list_fonts`); template faces resolve with `catalogFaceFiles` from the bundled and remote families only, never from the library. |
| Documents | no schema change (still v8) | Documents keep naming fonts by `FontRef.family` (any `source`); resolution happens at render time against bundled + installed fonts, so installing a font later makes existing projects render with it without editing them (no new field needed; nothing an older build would drop or misread). `source` stays informational. |
| Routes | `apps/engine/src/routes/fonts.ts`, contracts in `packages/api` (`fontLibraryList`, `fontInstall`, `fontInstallPath`, `fontDelete`, `fontUsage`) | Authenticated like every `/api` route. `POST /api/fonts/library?fileName=` octet-stream body, read with a running cap (413 `FONT_TOO_LARGE` as soon as it passes 64 MiB, or up front from `content-length`); `POST …/install-path {path}` (absolute, local mode only like path media); `DELETE …/:fontId` — an agent's request goes through `requireUserApproval` (card names up to five saved projects using the font), the editor window confirms itself; `GET …/:fontId/usage` scans ≤ 200 saved projects (`FontRef.family` resolving to the face's family or the face). |
| Every export path | planner + layer bake + Remotion | Text is a DOM layer on every path: native exports bake it (layer bake, `hybrid`), the Remotion path and stills render the composition; all load the snapshot's font URL (`/fonts/library/…`, signed for the headless browser). Layer-bake keys hash the font file (`keyFonts` → `filePath`), so installing or removing a font re-bakes. |
| Web | `apps/web/src/fonts/` (`store.ts`, `hooks.ts`, `preview.ts`, `FontPicker.tsx`, `FontsPage.tsx`, `ResolveFontsDialog.tsx`, `notice.ts`, `actions.ts`), `commands/fonts.ts` | Font menu (Properties ▸ Text font, Captions ▸ track style font): search; sections Project Fonts (missing ones marked), My Fonts, Bundled Fonts; every name drawn in its own face (private `jasper-preview-<n>` FontFaces, loaded when visible); Add Font… (file picker or dropping files on the menu), Resolve Fonts…, Manage Fonts…. Edit ▸ Preferences ▸ Fonts: installed faces grouped by family with a sample, style, weight, PostScript name, format, size, file; Add Fonts… / drop; Remove (confirmation names saved projects using it); repairs and read-only notices; bundled list. Graphics ▸ Resolve Fonts… / Add Fonts…. A project opening with missing fonts shows one warning toast with Resolve Fonts…. Uploads from the editor are loaded once with `FontFace` after install; a face this browser refuses is removed again and reported (the Player and the headless renderer are Chromium). ## Research and references

- OpenType spec (Microsoft): font file / table directory and TTC header — <https://learn.microsoft.com/typography/opentype/spec/otff>; `name` IDs 1, 2, 4, 6, 16, 17 and PostScript name characters — <https://learn.microsoft.com/typography/opentype/spec/name>; `OS/2` `usWeightClass`, `fsSelection` bits 0/5/9 — <https://learn.microsoft.com/typography/opentype/spec/os2>; `head` magic, `macStyle` — <https://learn.microsoft.com/typography/opentype/spec/head>; `fvar` axis records — <https://learn.microsoft.com/typography/opentype/spec/fvar>.
- W3C WOFF File Format 1.0 — <https://www.w3.org/TR/WOFF/> (stored tables when `compLength = origLength`); WOFF 2.0 — <https://www.w3.org/TR/WOFF2/> (known-tag table, UIntBase128, transform version semantics: glyf/loca 0 = transformed, 3 = null; other tables 0 = null).
- Container-length validity: [WOFF 1.0 §5](https://www.w3.org/TR/WOFF/) requires each decoded table to match its directory's `origLength`; [WOFF 2.0 §5](https://www.w3.org/TR/WOFF2/) requires the decoded block to match the sum of directory table lengths. Negative fixtures preserve real valid table bytes and alter only their length contract, so unrelated invalid naming/head data cannot satisfy the expected refusal. These cases establish format refusal, not measured peak-memory protection.
- CSS Fonts 4 — <https://www.w3.org/TR/css-fonts-4/>: a variable face's `wght` follows the used `font-weight` within its descriptor range (why one file is listed under several weights).
- Premiere's behaviour (Adobe Community threads, not official documentation): opening a project with missing fonts shows a "Resolve Fonts" dialog; fonts that cannot be synced are "Unresolvable (Will be substituted with default font)"; replacement is a separate "Replace Fonts in Project" command — <https://community.adobe.com/t5/premiere-pro-discussions/resolve-fonts-unresolvable-will-be-substituted-with-default-font/m-p/11618686/highlight/true>, <https://community.adobe.com/t5/premiere-pro-discussions/remove-missing-font-from-project-or-remove-resolve-fonts-warning-window/m-p/15199271/highlight/true>. JasperEditor's Resolve Fonts installs files instead of syncing a font service (assumption: the user has the font files).
- Assumption (unverified against Premiere's file format): the family string Premiere stores is the PostScript name; loose matching also covers full and legacy family names.

## Limitations

- Installs through MCP / `install-path` are validated structurally only; the browser check (Chromium's font sanitiser) runs for installs from the editor. A font Chromium refuses but the reader accepts would render with the browser's fallback without `FONT_FALLBACK`. The test generator's WOFF2 (null-transformed glyf/loca) is such a file: it reads correctly but Chromium refuses it — so WOFF2 browser coverage uses real @fontsource files.
- Motion-graphics bundles (Remotion projects) keep loading their own fonts; library fonts are not injected into their pages.
- A library family with a bundled family's name is shadowed by the bundled one (deterministic for existing projects); its faces are still reached by PostScript / full name.
- WOFF / WOFF2 collections are refused; TTC/OTC are split into faces.
