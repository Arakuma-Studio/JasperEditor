Scope: `apps/web/test/**`, `packages/ui/test/**`, and the test-only production seams they owned. Tests with the same independent contract share a six-point bar rationale below; each row identifies its rationale.

## Six-point bar for surviving checks

Each profile states, in order: **(1) independent source; (2) observable failure; (3) independent oracle; (4) stable seam; (5) refactor tolerance; (6) lowest nonduplicate owner.**

| Profile | Full bar justification |
| --- | --- |
| UI primitive | (1) S05 CT/TY/TS/MN/TT acceptance criteria explicitly specify the interaction or accessibility behavior. (2) A user's entry, drag, menu, toast, tree navigation, or recovery action yields the wrong value or state. (3) Literal input/output values and interaction outcomes come from the spec, not component internals. (4) Tests render public `@jasper/ui` components or use the documented toast store. (5) They observe callbacks, accessible state, or rendered feedback rather than private call shape or CSS structure. (6) No stronger test owns these reusable primitive contracts; app/E2E tests cover their larger workflows. |
| UI tree performance | (1) S05 CT-044 requires virtualization and screen-reader row counts. (2) A 1,000-item project tree becomes unresponsive or reports the wrong accessible count. (3) The 1,000-node fixture and small rendered subset are independent of its slicing logic. (4) The public `TreeList` is rendered. (5) A different virtualization algorithm still passes. (6) Higher layers do not exercise a long accessible tree. |
| UI color | (1) S05 CT-014 specifies a hex-input color picker; hexadecimal channel ordering and invalid-input rejection are standard format rules. (2) A picker accepts an invalid color or changes the wrong channel/alpha. (3) Literal color vectors are independent. (4) Public `@jasper/ui` color conversion API, used by ColorPicker. (5) Internal picker and parser changes can preserve these outputs. (6) No other test owns picker hex conversion. |
| Source workflow | (1) S03 SRC-001/003/004 and AC-SRC-1 require recent media, document-backed undoable marks, focused I/O commands, and marked insert/overwrite. (2) Opening, marking, undo, or source editing changes the wrong item, clips, or playhead. (3) Expected IDs, flicks, frames, and document state come from fixture input and spec. (4) Source action functions and command dispatcher are seams used by SourceMonitor and toolbar/keymap production callers. (5) Tests assert document/transport results, not internal command arrays or view markup. (6) E2E smoke covers generic timeline edits, not Source-specific marks/focus/hand-off. |
| PWA fetch | (1) S05 PWA-004 requires Range, media/render, cross-origin, and non-GET traffic to bypass the service worker cache, and offline cache misses to fail cleanly. (2) Fetch interception breaks streaming/downloads or returns a non-error for an unavailable asset. (3) External request URLs and expected browser interception are literal independent cases. (4) Tests dispatch the service worker's public `fetch` event; they never call `classifyRequest`. (5) Internal route classification and cache strategy may change. (6) `e2e/pwa.spec.ts` owns only production registration and `/api/capabilities` bypass, so these cases cover distinct routes and offline behavior. |
| PWA registration | (1) S05 PWA-004 says register only in production web builds with service-worker support. (2) Development/Electron pages get a worker or production pages lack one. (3) The environment truth table comes from the spec. (4) `registerServiceWorker` is the entry called by the app; the test observes its browser registration call. (5) Refactoring the private gate preserves the truth table. (6) E2E checks successful production registration only; this is the lowest seam for negative environments. |
| Build configuration | (1) S11 ANM-023 explicitly requires anime.js modules in `vendor-anime`. (2) Shipping them elsewhere invalidates the dedicated cached chunk and changes web download behavior. (3) The chunk name and anime.js subpaths come from the animation spec. (4) Vite's public `build.rollupOptions.output.manualChunks` config is exercised; the test-only `vendorChunk` export is gone. (5) The mapping function can be renamed or reorganized. (6) Build gate confirms bundling succeeds, but no other test checks this cache contract. |
| Notices | (1) S11 FIX-010 requires About to name anime.js/MIT and expose the shipped JavaScript notices. (2) A user cannot find or read notices, or sees no error when the asset is unavailable. (3) The package/license and public asset path are specified independently. (4) Rendered `ThirdPartyLicenses` UI is exercised through links and opening the details disclosure. (5) Copy and component structure may change as long as license and asset access remain. (6) LGPL notice tests cover a different dependency; the notices generator checks file content, not About access. |
| Export filename | (1) S05 EX-012 requires legal export filenames; export appends the container extension. (2) A download receives illegal path characters, a doubled `.mp4`, or an empty name. (3) Literal source/expected names are independent examples. (4) `sanitizeFileName` is the production seam used by ExportMode and quick export. (5) Its implementation can change while names remain valid. (6) Export E2E checks successful download, not normalization edge cases. |
