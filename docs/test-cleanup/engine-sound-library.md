# Engine sound library test cleanup

Scope: nine original files, 109 original test declarations; two moved/rebuilt index owners now live in a tenth file (including `sound-packs.test.ts`, reassigned from the engine-sound owner). Every row below records one original declaration. Tests were read with `sounds/{starter,library,index-job,roots,search,analysis,analysis-core,visual,packs,service}.ts`, semantic frontend/tokenizer/score/cache/runtime/service, API schemas and route owners.

Independent sources: [sound-design spec](../specs/12-sound-design.md) §§1/2.1, P1-R4, P6-R1, P6-E14; [sound-design work note](../wp-notes/sound-design.md) WP1.2 review findings and WP-E9 mathematical/compatibility recipe; [architecture](../ARCHITECTURE.md) D-47; [agent contracts](../../AGENTS.md) §§0/2/3; HTTP Range and CLAP tokenizer/input protocols. Obsolete attribution-sidecar requirements are superseded by AGENTS and were not retained.

For each retained row, the **source** is independent of the implementation; **oracle** identifies the fixed input, independently defined outcome or alternate algorithm; **bug** is the caller-visible regression; **seam/uniqueness** identifies the lowest owner for that failure. Expectations concern returned values, durable bytes, protocol results, errors or resource policy, so behavior-preserving identifier/internal-layout refactors preserve them. The index-job fixture virtualizes filesystem/media I/O; actual indexer walks, schema validation, stores, commits and follow-up decisions remain production code. Concurrent root changes happen through the real root store during the analyzer dependency call; no scan method is replaced. The Worker URL fixture computes real DSP output and uses filesystem receipt/release barriers, a native uncaught error and a withheld reply; production code owns cancellation, error mapping, timeout and recovery. No arranged Worker result, constructor factory or replaced scan method remains. No assertion of private pass count or diagnostic execution mode remains in this scope.
