# Engine Sound Check test cleanup

Scope: all ten `apps/engine/test/sound-check*.test.ts` files, their shared fixture, and production owners `sound-design/{check,check-findings,check-proposal,stems,visual,report-store}.ts` / route wiring. Baseline: 65 declared cases; final: 63 (one remains opt-in). This audit does not claim broader engine/audio coverage.

Independent contract sources: [sound-design spec §2.6 and P5/P6](../specs/12-sound-design.md), [sound-design work note](../wp-notes/sound-design.md) (Phase 5 engine review, WP5.1, WP6.5b, B11/B13, codec-aware delivery), root [AGENTS.md](../../AGENTS.md) persistence/security/fidelity rules, and published API schemas in `packages/api/src/sound-check.ts`. The work note records independent observed failures and intended outcomes; expected values are not obtained by reading current production branches.

The six-part retention bar is applied to every row below. Each row identifies its independent source, recognizable failure and independent oracle. Unless a row says otherwise, its stable seam is authenticated HTTP job/result and persisted document/file data; it asserts codes, state and measured audio rather than collaborator shape. `stems` rows compare separate production render paths under the explicit parity contract; `ending-fade` uses the production-used issue-emission boundary; store rows use its production-used save/get/prune boundary with real files; pure delta uses its production-used deterministic result boundary. Those observations survive helper renames/reorganization and behavior-preserving refactors. Each row explains why another surviving owner does not supersede it. Shared fixture generation is arrangement, not the oracle. Mocked fix validation in the fade tests only suppresses unrelated command construction; the real production finder decides whether ENDING is emitted.

## Removed infrastructure and performance

Two redundant real-audio executions are consolidated into the existing clean-report/visual request. The true-peak fixture uses external FFmpeg on a rendered WAV and one whole-Mix dB correction instead of up to four single-clip calibration iterations (up to six full checks become two checks plus one WAV/oracle run). Report eviction uses explicit mtimes rather than 45 ms of sleeps. The eviction test now checks the actual 32-report and 16 MB product bounds; this intentionally costs 33 small atomic saves and one bounded 16 MB string instead of preserving test-only lower-limit configuration.

Production-only cleanup: `endsWithFadeOut` and `SOUND_CHECK_STORE_LIMITS` become private; report-store `now`, `perProject`, `maxBytes` option hooks and exposed instance limit fields are removed after verifying all callers. Runtime defaults and report behavior are unchanged. An unused type export from a test is removed. No dependency, shared-fixture, snapshot or configuration is removed because all still have callers.

`endingFindings` now accepts the eight context fields it actually reads: `seq` supplies the Mix strip and command target; `F` converts frames to flicks; `range` and `duration` decide whether the checked interval reaches an edge; `tc` formats the reported time; `add` emits the finding; and `dryRun` / `commandFix` validate and construct its offered fix. This is a type-only narrowing of an existing production-used boundary. It corrects the rewrite's misleading cast from a partial fixture to all of `FindCtx`, which failed TypeScript validation. The fixture now supplies a typed, unreachable `commandFix` that throws if called after its explicit dry-run refusal. No runtime signature, new hook, wrapper or export is added.

The long-sequence benchmark remains opt-in. The real issue/fix/recheck renders, codec parity and restart tests remain expensive because they protect actual DSP/export/persistence contracts; mocked replacements would lose those bugs. Lifecycle's bounded condition polling remains. Two 150 ms absence-observation waits cannot safely become immediate assertions without a public prune-completion signal; introducing a test-only production hook would increase coupling, so they remain.

## Validation and timing

Measured on the shared 8-vCPU AMD EPYC-Genoa / 15 GiB host, Node 20.19.0, pnpm 10.34.5, Vitest 4.1.11 and system FFmpeg 6.1.1, with required oracles and two workers. The render workstream and then audio/motion validation occupied the other allowed slot; load average was 3.28 / 3.20 / 2.65 at one recorded sample. These scoped measurements do not establish whole-suite or CI savings; the root report owns the comparable full-suite measurement.

The ten-file target passed **62 cases in nine files**, with the existing long-sequence opt-in benchmark skipped (one case/file). Vitest wall time was **120.81 s**; GNU command wall time was **121.99 s**, user CPU 273.23 s and system CPU 72.64 s. The new peak fixture passed its independent −0.2 dBTP check, successful offered fix, compliant re-check and positive limiter gain-reduction assertion. No baseline product failure was found in this area.

Four alternating baseline/final runs selected only the peak case. Each process started a new runner and generated/registered the same real media; the baseline test source came from `8b4c8936`, while all production sources, environment, runner flags and oracle versions stayed constant. All four passed, without retries.

| Measurement | Baseline runs | Optimized runs | Mean saving |

| Peak test body | 10.079 / 10.613 s | 4.595 / 4.985 s | 5.556 s (53.7%) |
| Entire selected-test process | 30.554 / 27.635 s | 22.673 / 25.546 s | 4.985 s (17.1%) |

The body improvement is consistent across the two pairs. Import/startup and concurrent-host variation limit the process comparison: optimized process time varied by 2.873 s. The operation removed is repeated full check/calibration work, rather than an assertion or isolation boundary. The original full-suite peak body was 9.493 s; in the changed ten-file run it was 4.178 s, but those two runs are not treated as a controlled comparison.

The slowest retained case in the changed target was stale/invalid proposal checking at 8.391 s, followed by dialogue-pause discrimination at 7.567 s, proposal what-if attribution at 7.057 s and jointly safe fixes at 6.294 s. They perform distinct real before/after audio or proposal workflows specified above; replacing them with simulated findings would lose their unique integration failures. The main Sound Check file took 53.572 s including its hooks, and the P6 file took 46.543 s; they remain the largest local contributors.
